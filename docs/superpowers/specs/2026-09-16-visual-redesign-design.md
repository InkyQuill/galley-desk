# Визуальный редизайн Galley Desk

Согласовано интерактивно (моки в `.superpowers/brainstorm/`) 2026-09-16. Меняется визуальный слой окна книги и связанные компоненты редактора — сама логика команд/сохранения/ревизий не трогается.

## Объём и этап

Заход затрагивает только **Galley Desk** и **`@inkyquill/galley-editor`** (общий редактор, откуда берётся `ReviewEditor`). Galley Pad и Pocket Editor — вне объёма; заметка о переносе той же схемы правок/сигналов в Pocket Editor (рендер поверх markdown, а не поверх сырых токенов) зафиксирована отдельно как будущая работа и здесь не реализуется.

Этот заход — **моки**, не финальная реализация: собираем утверждённые интерактивные экраны на статичных/локальных данных, без реального IPC (`window.desk.*`) и без бэкенд-логики. После утверждения моков — отдельный план на перенос в рабочее приложение.

### Где живут моки

Отдельный пакет-прототип в монорепо (например `packages/desk-prototype`): Vite + React + Tailwind v4, открывается в обычном браузере, не требует Electron. Локальный React state вместо `window.desk.*`, фикстуры вместо реальных книг/глав. Не трогает `apps/desktop` до отдельного решения о переносе.

### Стилевой движок

**Tailwind v4** — utility-first, `@theme`/`@theme inline` умеет мапиться на CSS-переменные темы, которые резолвятся в рантайме (тема выбирается пользователем, не на сборке) — альтернативы (vanilla-extract, Panda CSS) не дают здесь ощутимого преимущества при статической типизации токенов, которая не так важна для прототипа. Дизайн-токены `@inkyquill/galley-themes` (`--app-*`) остаются источником истины; Tailwind обращается к ним через `bg-[var(--app-panel)]` или конфиг-алиасы, не дублирует палитру.

## Направление

Референс — Obsidian/Shosho: flat, мягкий, без тяжёлых рамок. Из трёх предложенных направлений выбрана «тёплая бумага» (тёплый светлый фон, карточки вместо блоков с бордером), но не как фиксированная палитра — как язык, который ложится на существующий каталог тем `@inkyquill/galley-themes` (13 встроенных тем + «Системная»).

## Токены и тональная система

Приложение уже подключает CSS-переменные темы (`--app-bg`, `--app-text`, `--app-panel`, `--app-panel-muted`, `--app-border`, `--app-hover`, `--app-focus`, `--app-text-muted`, `--app-error-*`, `--app-dialog-shadow`, `--app-backdrop`) через `windowContainerStyle`, но `app.css` их почти не использует — большинство границ и подложек сейчас строятся вручную через `color-mix(in srgb, currentColor N%, transparent)`. Редизайн переводит компоненты на реальные токены:

- **Три уровня тона вместо рамок**: `bg` (внешний рельс — оглавление, панель рецензии) → `panel` (приподнятые поверхности — колонка текста, попапы, flyout) → `panelMuted` (второй план — заметка главы, карточки записей, инпуты, неактивные чипы).
- Разделение между зонами — не `border`, а разница тона; `border` токен остаётся, но используется точечно (например, тонкий разделитель в открытом меню «⋯»), не как основной приём.
- Активные состояния (активная глава, активный вид, активная кнопка сегмента) — заливка тоном `hover`/`panelMuted`, не рамка и не подчёркивание.
- Колонка текста главы (`.book__text`, `.book__source`, `.book__comparison`) перестаёт быть блоком с бордером — это приподнятая карточка: `panel` + мягкая тень (по образцу `--app-dialog-shadow`, но легче — понадобится собственный токен тени карточки, см. «Новые токены»), с обычным скруглением, отцентрированная, ширина по-прежнему берётся из настройки `lineWidth` (`contentWidthStyle` не меняется).
- Попапы (`RecordPopup`) и flyout выбора сигнала (`SignalFlyout`) используют тот же приём карточки (`panel` + мягкая тень) вместо текущей рамки.
- Семантика цвета сигналов (note / change_required / warning / review) не меняется — это термины Pocket Editor, редизайн их не переопределяет.

### Новые токены (расширение `@inkyquill/galley-themes` разрешено)

Пакет тем можно и нужно дополнить, если существующих токенов не хватает:

- `app.accent` — акцентный цвет интерфейса (подсветка активного элемента, фокус-обводка инпутов, цвет ссылок в чроме), отдельно от `app.focus` — `focus` семантически кольцо фокуса редактора и не обязан совпадать с акцентом интерфейса.
- `app.cardShadow` (или переиспользование `dialogShadow` с меньшей непрозрачностью на уровне компонента) — тень карточки колонки текста/попапов, чтобы не жёстко хардкодить `rgba(...)` в `app.css` и она корректно менялась по темам (тёмные темы — тень темнее и заметнее, светлые — мягче).


Оба токена добавляются во все 13 встроенных тем каталога галереи (координация с репозиторием `galley-editor`, см. ADR 0003).

## Типографика: два независимых шрифта

Сейчас один `AppearanceSettings.fontFamily` красит одновременно интерфейс и текст книги (`windowContainerStyle` ставит `fontFamily` на весь контейнер). Разводим на два независимых поля:

- **Шрифт интерфейса** (`AppearanceSettings.uiFontFamily`) — оглавление, шапка, кнопки, панель рецензии, попапы. По умолчанию **Geist** (выбран из сравнения Inter / Geist / Manrope), с фолбэком `system-ui, sans-serif`.
- **Шрифт книги** (`AppearanceSettings.fontFamily`, сохраняет текущее имя поля и назначение) — текст главы, сравнение, исходник. По умолчанию **Literata** (с засечками, для чтения), с фолбэком `Georgia, serif`.

Оба поля — свободный текст, как сейчас `fontFamily` (пользователь может вписать любой системный шрифт), просто с разными дефолтами и разным местом применения. `windowContainerStyle` ставит `uiFontFamily` на контейнер (наследуется всем чромом) и передаёт `fontFamily` только в переменную `--ge-font-body` (редактор Galley) плюс на элементы читаемого текста (карточка текста/сравнения/исходника), а не на весь контейнер.

Панель «Оформление» получает два текстовых поля вместо одного («Шрифт интерфейса» / «Шрифт книги»); валидация в `settings.ts` (`validateAppearance`) и `DEFAULT_APPEARANCE` в обоих местах (`main/settings.ts`, `renderer/appearance/Appearance.tsx`) дублируют проверку на новое поле по образцу существующей.

## Иконки вместо текстовых кнопок в шапке

Частые действия — иконка с `title`/`aria-label` (для доступности и скринридеров, не только hover-tooltip):

- Поиск по главе (лупа) — сворачивается в иконку в верхней панели; клик разворачивает строку `ChapterSearch` на месте (как сейчас), повторный клик или Escape без запроса — сворачивает обратно. Экономит место в шапке, когда поиск не нужен.
- Переключатель вида («Текст» / «Сравнение» / «Исходник») — сегментированный контрол из трёх иконок (документ / сравнение / код) вместо трёх текстовых кнопок.
- Режим Zen — иконка `target`/`target-off` (см. «Иконки»), тултип «Режим Zen».

Редкие действия уходят под меню-троеточие (`⋯`) в конце шапки: **Оформление** и **Закрыть книгу** — там текст рядом с иконкой уместен, это открывающееся по клику меню, а не постоянный ряд кнопок.

Контекстные элементы — чип состояния сохранения, «Перечитать главу» (только при ошибке), «Открыть внешнюю версию» / «Экспортировать черновик…» (только при внешнем изменении) — **не трогаем**: они появляются только при реальном событии и не создают постоянного шума, прятать их под меню не нужно. Чип состояния сохранения меняется только косметически (точка/цвет вместо текста для состояния «Сохранено»; текст остаётся для ошибок и предупреждений — там он несёт смысл, а не декорацию).

## Сайдбар рецензии (`ReviewList`)

Сейчас каждая запись — предложение текстом («Правка: before → after» / «Сигнал [type]: comment»), список быстро превращается в стену текста. Новый формат строки записи:

- Иконка формы записи слева — **карандаш** для правки, **молния** для сигнала (форма фиксирует «что это», а не «какой именно тип сигнала» — четырёх разных пиктограмм под note/change_required/warning/review не заводим).
- Цвет иконки — по типу: свой цвет правки и свой цвет на каждый из четырёх типов сигнала (переиспользуем текущую Pocket-палитру точек).
- Рядом — одна строка обрезанного текста (`text-overflow: ellipsis`, без переноса): для правки — `before → after` в исходном виде, для сигнала — комментарий, если есть, иначе название типа.
- Полный текст, статус (конфликт/недоступна) и действия — только в открытом попапе по клику, как сейчас.

## Разметка правок и сигналов в редакторе

Меняется способ показа правок и сигналов внутри текста (сейчас, судя по `markers.ts`, встроенный инлайн-дифф). Новая схема:

- **Правки**: в тексте виден только результат (`after`) — удалённые символы (`before`) инлайн не показываются нигде, даже зачёркнутыми. Сама правка подсвечена мягкой заливкой фона (цвет правки, невысокая непрозрачность) поверх изменённого текста.
- Иконка **карандаша** выносится на поля редактора (гуттер), по одной иконке на каждую правку — если на строке несколько правок, гуттер показывает несколько иконок рядом (сортировка по позиции внутри строки), не сворачивает их в «+N». Иконка кликабельна и открывает попап правки — так же, как сейчас клик по самой подсветке.
- **Оригинал (`before`)** показывается в flyout. Flyout появляется при **двух** триггерах — курсор находится внутри диапазона правки (работает с клавиатуры) **или** наведение мышью на подсветку (быстрый предпросмотр без перемещения курсора). Оба ведут к одному и тому же flyout-компоненту.
- **Сигналы**: не подчёркивание (волнистое подчёркивание зарезервировано под будущую проверку орфографии — не путать с сигналами рецензии). Сигнал — **фоновая заливка примерно на треть высоты строки** позади символов (снизу, как маркер-хайлайтер), цвет — по типу сигнала. Иконка **молнии** цвета сигнала выносится на поля редактора рядом (по той же логике одна иконка на сигнал, не сгруппированная).
- Оба вида полевых иконок (карандаш, молния) используют общую колонку гуттера; порядок сверху вниз соответствует порядку записей в тексте, не панели рецензии.

## Иконки

Инвентарь (нужен для сравнения наборов, см. отдельный визуальный чек-пойнт): поиск, очистить поиск, пред./след. совпадение, три вида (текст/сравнение/исходник), Zen (вход/выход), меню «⋯», Оформление (слайдеры), Закрыть книгу, отменить/повторить применение (сравнение), открыть внешнюю версию, экспортировать черновик, перечитать главу, правка (карандаш), сигнал (молния), отсутствующая глава (предупреждение), применить/сохранить (галочка), удалить (корзина), отмена/закрыть (крестик), разворот попапа/чипа (шеврон), элементы окна для мока window frame (свернуть/развернуть/закрыть).

Выбор по итогам сравнения: **Tabler Icons** — основной набор (обводка 2px, большое покрытие ~4900 иконок). **Phosphor** — резервный набор для точечных случаев, когда в Tabler нет подходящей иконки; подмешивать без необходимости не стоит (риск разнобоя обводки/скруглений, которого и старались избежать).

Режим Zen — иконка `target` (вход) / `target-off` (выход) вместо уголков разворота: точнее передаёт смысл «сфокусироваться на тексте», а не «развернуть окно».

## Кастомный window frame и системное меню

В этом заходе — только визуальный мок в прототипе (как будет выглядеть заголовок окна со своими кнопками и стилизованным меню вместо системного), без реальной настройки `BrowserWindow` (`frame: false`/`titleBarStyle`) и drag-region в Electron — это отдельная задача с учётом различий macOS/Windows/Linux.

## Иконка приложения

Уже решена ADR `docs/adr/0004-application-icon.md` — знак и SVG-исходники (`apps/desktop/assets/branding/galley-desk-icon(-mono).svg`) существуют. В моках используем как есть (например, в стилизованном меню/заголовке окна), встраивание в executable/Dock/таскбар — отдельная задача вне этого захода.

## Компоненты: кнопки, инпуты

- Кнопки — плоские, без рамки; фон появляется только на hover/active (`panelMuted`/`hover`), текст — `text` или `textMuted` в зависимости от значимости; опасное действие (Закрыть книгу) — текст `errorText`, без заливки в покое.
- Инпуты (фильтр глав, поиск по главе, поля панели «Оформление») — заливка `panelMuted`, без рамки, фокус — обводка `accent`.

## Ширина колонки чтения

Дефолт `lineWidth` меняется с 720 на **700px** — как у референса Obsidian. Границы настройки (320–1600) и сам механизм (`contentWidthStyle`, пользовательская настройка в «Оформлении») не меняются, меняется только значение по умолчанию (`DEFAULT_APPEARANCE.lineWidth` в `main/settings.ts` и `renderer/appearance/Appearance.tsx`).

## Что не меняется

- Grid-структура `.book__body` (оглавление / контент / панель рецензии), Zen-режим (скрытие панелей + постоянная кнопка выхода), порядок Escape.
- Границы и механизм настройки ширины колонки (`lineWidth`), кроме значения по умолчанию (см. выше).
- Семантика и цвета типов сигналов.
- Русскоязычные подписи и термины (`CONTEXT.md`).

## Границы работы

- Этот этап — прототип в новом пакете (см. «Где живут моки»), не правки в `apps/desktop`. Перенос утверждённых моков в `apps/desktop/src/renderer/**`/`app.css` и в `@inkyquill/galley-editor` (репозиторий `galley-editor`) — отдельный план после утверждения.
- Новые токены (`accent`, `cardShadow`) и дефолтные значения `uiFontFamily`/`fontFamily` координируются с пакетом `@inkyquill/galley-themes` (репозиторий `galley-editor`, ADR 0003); в прототипе используются как обычные CSS-переменные/фикстуры без публикации пакета.
- `AppearanceSettings` (тип в `shared/api.ts`), `main/settings.ts` (валидация, дефолты) и `renderer/appearance/Appearance.tsx` (форма, дефолты) при переносе меняются согласованно — это одна логическая единица настройки, не отдельные подзадачи.
- Pocket Editor и Galley Pad не трогаются в этом заходе.
