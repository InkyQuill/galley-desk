# Диагностика и рабочее пространство Galley Desk

Дата: 2026-09-17. Основание: запрос пользователя о логах и четыре замечания к UX;
дополнение — [UX-pass Claude](../../reviews/2026-09-17-ux-pass.md), истории №1, 6–12.
Статус: UX-спецификация дополнена по ревью; этот документ не подтверждает
выполнение задач. Статус диагностики проверяется по отдельному плану.
Базовая редакция: `fb76edd`, Editor/themes 0.15.0. Известное падение выделения
сигнала на macOS отложено пользователем и не входит в эти работы.

## 1. Диагностика

Постоянные локальные JSONL-логи в `app.getPath('userData')/logs`.
Один активный файл `main.log`, две ротации `main.1.log`, `main.2.log`;
каждый до 2 MiB, запись до 8 KiB, очередь до 256 записей. Переполнение
агрегируется в счётчик пропущенных записей. Логи не отправляются по сети.
Включены по умолчанию; не писать успешную операцию на каждое нажатие клавиши.

Запись: UTC-время, уровень, процесс, sessionId, версия приложения и сборки,
код события, безопасный код ошибки, очищенные stack frames. Начало сессии
содержит ОС/архитектуру, Electron/Chromium и версии Editor/themes. События:
запуск/штатное закрытие, ошибки IPC/сохранения/watcher/recovery, необработанные
ошибки main/renderer, падение renderer/дочернего процесса. Сохранить stderr.

Не записывать содержимое документов, комментарии, YAML, аргументы команд,
названия книг, абсолютные пути пользовательских файлов и произвольный
Error.message. Stack хранить только как распознанные позиции в коде приложения
без первой строки ошибки и без абсолютного пути; неизвестные frames опускать.
Корреляция IPC — отдельный requestId, без полезной нагрузки команды.
Renderer сообщает ограниченные структурированные события через проверяемый
IPC, main ограничивает размер и частоту (20 событий/секунду на renderer).

Ошибка записи лога не блокирует сохранение книги и не вызывает рекурсивный лог.
При штатном выходе ожидать flush не более 500 мс. Фатальная ошибка main
фиксируется best effort и остаётся фатальной; нельзя продолжать работу в
неизвестном состоянии ради записи лога. Аварийный путь имеет ограниченную
синхронную запись; нельзя обещать лог при SIGKILL/отключении питания.

«Диагностика» доступна в меню приложения и на экране недавних книг:
версия/сборка, статус файлового журнала, «Открыть папку логов»,
«Скопировать сведения о версии». При отказе shell.openPath — видимая ошибка.
Скопированные сведения не содержат путей и текста книги. Без экспортера книг,
телеметрии, отдельного окна просмотра логов и нового сервера диагностики.

## 2. Действия рядом с объектом

У заголовка «Оглавление» три иконки со стилизованными подсказками:
«Добавить главу», «Сортировать главы», «Найти главы в папке» (Discovery).
Discovery рассматривает только выбранную папку и прежние правила ignored_files;
показывает выбор файлов и добавляет только явно отмеченные. Поиск новых книг
или рекурсивный обход не добавляются.

Карточка главы: название в одну строку с эллипсисом, ниже имя файла,
отдельная кнопка меню. Кнопки не вложены друг в друга. Меню относится к этой
главе независимо от активной: «Убрать из оглавления», «Переместить в корзину…».
Отсутствующую главу нельзя открыть, но можно убрать из оглавления. Корзина
требует существующего подтверждения с именем файла и sidecar. Весь прежний
flush/conflict/recovery контроль сохраняется.

Меню книги содержит переименование книги, оформление, диагностику и закрытие.
Большой универсальный диалог BookManagement удаляется после переноса действий.
Формы создания/Discovery остаются отдельными небольшими диалогами, а не
встраиваются постоянно между главами.

Сортировка — явная операция: меню «По имени файла» или «По названию»;
натуральный порядок ru/en, числа 2 перед 10, равные ключи сохраняют порядок.
Она изменяет порядок всех глав, включая скрытые фильтром; при активном фильтре
показать это в тексте подтверждения. Перед применением показать список нового
порядка и кнопки «Применить»/«Отмена». Отмена не пишет манифест. Сортировка
не переименовывает файлы, сохраняет UUID, sidecar и активную главу. Drag-and-drop
перестановка глав не входит в эту итерацию.

## 3. Размеры сайдбаров

Предлагаемые значения: оглавление 315 px, рецензия 336 px (прежние 210/224 ×1.5).
Каждая ширина в пределах 240–560 px, шаг клавиатуры 16 px. Между колонками
разделитель с зоной попадания 6 px: pointer capture, cursor col-resize,
role=separator, aria-orientation=vertical, значения и название стороны.
Стрелки меняют ширину, Home/End — минимум/максимум; двойной клик — default.
Escape/pointercancel отменяют незавершённое перетаскивание.

Настройки глобальные для профиля, не для книги; сохранять после отпускания
мыши или серии клавиатурных изменений (250 мс), не на каждом pointermove.
Не терять appearance/positions при параллельной записи settings.json:
сериализовать весь read-modify-write всех писателей этого файла.

Центральной колонке оставлять минимум 480 px, ширины временно ограничивать
доступным местом без перезаписи предпочтений. Если два минимума не помещаются,
автоматически скрыть рецензию, затем оглавление. Две кнопки верхней панели
позволяют открыть нужный sidebar как overlay при узком окне. Overlay закрывается
по Escape/снаружи и возвращает фокус. При расширении предпочитаемые размеры
восстанавливаются; Zen скрывает панели и не меняет настройки.

## 4. Единый верхний chrome

Одна строка высотой 44 px вместо TitleBar 38 px + book__header. Слева иконка
и название книги (без повтора); справа сохранение, поиск, виды, переключение
панелей, Zen, меню и системные кнопки. Название сокращается раньше исчезновения
действий. При ширине <1100 px редкие действия (Zen/оформление) уходят в меню,
строка не переносится. Поиск открывает свою строку только по запросу.

Видимый свободный участок и название — drag; все кнопки/поля/попапы — no-drag.
Сохранить двойной клик для maximize на Linux, minimize/restore/close и flush
при закрытии. На macOS сохранить traffic lights и свободную область слева
82 px. Экран недавних использует тот же TitleBar без действий книги.
В Zen оставить единую строку с управлением окном и видимой кнопкой выхода
из Zen даже при ширине <1100 px; в этом режиме она не прячется в меню.

## 5. Метаданные в попапе

У правого края строки названия главы — иконка «Метаданные главы».
В тексте главы нет постоянного блока YAML/«Метаданные». Иконка есть и без
frontmatter (можно добавить); ошибка YAML отмечается на иконке и объясняется
в попапе. Попап шириной min(560px, viewport−32px), max-height viewport−80px,
со своей прокруткой. Внутри прежние просмотр/редактирование YAML и явное
сохранение исходника; защита sourceText/revision и предупреждение об Undo
сохраняются. В read-only доступен просмотр.

Escape/клик снаружи закрывают чистый попап. При изменённом черновике предлагают
«Продолжить редактирование»/«Отбросить»; при сохранении закрытие заблокировано.
Переключение главы/книги подчиняется тому же правилу, черновик не переносится.
Фокус после закрытия возвращается к иконке; текст книги и scroll не прыгают.

## 6. Zen и общие подсказки (истории №6, №7)

Zen включается и выключается одной комбинацией: Ctrl+Alt+Z / Cmd+Alt+Z (физическая клавиша KeyZ,
работает в русской раскладке). Поддержать кнопку и тот же пункт меню.
Комбинация действует в окне книги, включая фокус в редакторе/поиске;
повтор keydown и IME composition не переключают режим повторно. Она не
сохраняет и не отбрасывает незавершённые формы; открытый модальный диалог
блокирует переключение до завершения формы. Undo/Redo остаются прежними.

Escape никогда не меняет Zen, в том числе без открытых слоёв и при двойном
нажатии. Сохранить порядок закрытия существующих слоёв: popup → flyout →
карточка → оформление/меню → поиск → подсказка редактора. Новые диалоги,
metadata, overlay и активный resize сначала обрабатывают Escape сами;
один Escape не должен закрывать несколько слоёв. Dirty/saving metadata
сохраняет правила §5.

Единый Tooltip для всего принадлежащего приложению UI: тема, UI-шрифт и
размер из «Оформления», текст и отдельная строка сочетания клавиш. Hover
(задержка 300 мс) и keyboard focus показывают подсказку; blur/уход указателя
и Escape скрывают. Она не получает фокус, не содержит действий и не мешает
закрытию активного слоя. role=tooltip и aria-describedby дополняют, но не
заменяют accessible name кнопки. Подсказка не обрезается контейнером и не
выходит за viewport. Нативные title-подсказки заменить в toolbar, режимах,
оглавлении, рецензии, маркерах, поиске, оформлении и системных кнопках;
не удалять свойства данных title или SVG <title>. DOM-маркеры редактора
подключаются к той же реализации через адаптер.

## 7. Поиск и фильтр оглавления (истории №8, №9)

Новый непустой запрос сразу показывает и подсвечивает первое совпадение,
согласованное со счётчиком 1/N. Фокус остаётся в поиске: можно непрерывно
печатать. Enter/Shift+Enter и стрелки переходят к следующему/предыдущему
результату циклически. Пустой запрос и отсутствие совпадений снимают
поисковую подсветку без прыжка к началу. Смена главы/области начинает с
первого результата; изменение ревизии пересчитывает результаты и ограничивает
текущий индекс, но само по себе не вызывает повторную прокрутку. Не менять
literal UTF-16 поиск и его области: производный текст в Текст/Сравнение,
исходный текст в Исходник; заметки и комментарии не искать.

Фильтр оглавления ищет подстроку и в названии, и в относительном пути,
независимо от регистра, с trim запроса. `012` находит `chapter-012.md`,
`5` — любое название/путь с `5`, включая `chapter-005.md`; числовой парсер
и ранжирование не нужны. Пустой фильтр показывает все главы в spine-порядке,
включая missing. Фильтр не переключает главу и не меняет manifest.

## 8. Возврат к чтению (истории №1, №11)

«Открыть папку…» и «Недавние» восстанавливают одну сохранённую главу,
anchor и прокрутку. Сопоставление — по bookId, как уже делает main при
обновлении недавних; не по отображаемому названию. Для новой книги, удалённой
или missing сохранённой главы — первая доступная запись manifest; если их
нет — прежнее пустое состояние. `_index.md` не исключать автоматически:
состав и порядок оглавления остаются выбором автора. Отмена выбора папки
ничего не меняет. Не создавать отдельное хранилище позиции.

Текст → Сравнение сохраняет видимое место чтения, Сравнение → Текст — место,
до которого пользователь прокрутил сравнение. Основной ориентир — первый
видимый текстовый anchor (UTF-16 в производном тексте) и его вертикальный
отступ; selection/caret не заменяет viewport-anchor после ручной прокрутки.
Пиксельный scrollTop двух разных представлений не эквивалентен. Если anchor
попал в удалённый фрагмент, использовать ближайшую границу правки; ограничить
позицию актуальной длиной текста. На границе документа допустим clamp,
в остальных случаях отклонение — не более высоты строки. Не переходить
автоматически к первой правке; глава без правок также сохраняет место.

Не менять формат сравнения или геометрию поиска: наличие frontmatter в
текущем представлении само по себе не исправляется скрытием строк. Не
переносить scrollTop сравнения в сохранённую позицию текстового редактора.
Переключения сохраняют pending edits, Undo и текущие flush/conflict проверки.

## 9. Читаемая рецензия и регрессия Undo (истории №10, №12)

При 20–30 записях рецензии увеличение панели дополняется переносом текста:
для правки отдельные «Было» и «Стало», до трёх строк каждой части; для сигнала
тип и до трёх строк комментария. Пустые части обозначать «вставка»/«удаление».
Длинные слова переносятся; статус конфликта/недоступности виден отдельно.
Полный текст доступен через общий Tooltip на hover/focus и существующую
карточку по клику; большие preview ограничены viewport. Сохранить порядок
чтения, переход к месту правки и popup с Применить/Отклонить. Проверить 240,
336 и 560 px. Группировка, поиск по рецензии и виртуализация в эту итерацию
не входят.

Undo уже работает: добавить регрессию, не переписывать историю ввода.
Отдельно проверить изменение середины слова и границы абзаца: один Undo
отменяет одну завершённую группу ввода и связанную запись, Redo возвращает
их вместе; соседние записи не меняются. После flush/reopen проверяется
сохранённый текст/sidecar, но не обещается сохранение стека Undo на диске.

## Границы и приёмка

Linux и macOS, React 19, Electron Forge/Vite, Editor/themes 0.15.0,
существующие Tabler icons и theme tokens. Новые зависимости не требуются.
Без изменения Pocket-схем, режима предложений правок, формата sidecar или
поиска директорий книг. Не обновлять установленное приложение в рамках
написания плана. Два независимых плана: diagnostics и workspace-ux.

Приёмка: все действия доступны с клавиатуры; подтверждения удаления сохранены;
ширины переживают перезапуск; одна верхняя полоса; метаданные занимают место
только в открытом попапе; локальные ошибки диагностируются без содержимого
книги. Проверить 900/1280/1920 px, светлую/тёмную тему, Zen и масштаб 125%.

Дополнительная приёмка по UX-pass: обе точки открытия возвращают к чтению;
поиск сразу показывает первую находку без потери фокуса; фильтр ищет имя
файла; повторный Escape оставляет Zen; подсказки следуют теме и UI-шрифту;
30 правок читаются списком; Текст ↔ Сравнение сохраняет видимый абзац;
Undo/Redo атомарны для текста и записи. Кроме автоматических disk-backed
фикстур пройти сценарии на временной копии реальной книги (20+ глав,
frontmatter, 20–30 правок в главе), сохранив evidence и фактический результат
по каждой истории. Оригинал книги не менять. Если реальная книга или macOS
недоступны, отметить соответствующую приёмку как не выполненную.
