# Перенос оформления Galley Desk в сестринские проекты

Первичный снимок: 2026-09-27; сверка документа с кодом: 2026-10-28. Основной документ — [apps/desktop/DESIGN.md](../apps/desktop/DESIGN.md); продуктовая область — [PRODUCT.md](../apps/desktop/PRODUCT.md). Здесь только порядок переноса и границы ответственности, без второго набора токенов.

## Что считать общим

1. Тематический корень, семантические переменные `--app-*` / `--ge-*`, приоритет явно выбранной темы над ОС и живая смена `auto`.
2. Независимые шрифты/размеры UI и документа, локальная поставка шрифтов, спокойная типографическая иерархия.
3. Тональные поверхности, плоский документ, тени временных слоёв, формы и состояния базовых элементов.
4. Контурные иконки, единая тематическая подсказка, доступные названия, клавиатурный фокус и его восстановление.
5. Сужение вспомогательных панелей ради документа, перенос длинного текста и ограничение слоёв размерами окна.

Готовый общий runtime-пакет есть для **тем**, но не для всей оболочки. `DESIGN.md` и `.impeccable/design.json` — документация и образцы, а не опубликованная библиотека компонентов. В проекте на Svelte те же семантические правила можно реализовать без переноса React-компонентов. В Tauri оконное управление и разрешения остаются собственными. Конкретное распределение команд по тулбару определяется задачами принимающего продукта.

## Что остаётся специфичным для Desk

- Название, логотип, выбор папки книги, оглавление, «Было»/«Стало», три режима просмотра.
- Семантика сигналов и правок Pocket Editor, их цветовые пары, gutter и flyout — переносить лишь при наличии той же задачи рецензирования.
- Точные предпочтительные ширины двух панелей и минимальные размеры окна — подтверждать отдельно для принимающего продукта.
- Electron titlebar/IPC, хранилище настроек, сохранение и восстановление книг, диагностика.
- Идентификаторы DOM, CSS-префикс `book__`, пути к файлам, содержимое демонстрационной рукописи.

## Последовательность переноса

1. Прочитать локальный `AGENTS.md`, текущий `DESIGN.md`, проверить состояние рабочего дерева и версии общих зависимостей принимающего репозитория. Не заменять его существующий дизайн-документ автоматически.
2. Подключить совместимую опубликованную версию `@inkyquill/galley-themes` и сопоставить семантические роли. Текущие pins Desk — `0.17.0`; обновление версии — отдельное осознанное изменение. Исторический [экспорт каталога 0.15.0](reviews/evidence/design-system-2026-09-27/theme-catalog.json) помогает сравнивать, но не заменяет зависимость.
3. Установить тематический контейнер над всем интерфейсом и portal-root. Согласовать `colorScheme`, тему редактора и схему семантических отметок. Не забыть стартовый экран и popover.
4. Перенести типографику, поверхности, базовые состояния, радиусы и плотность из основного документа. Ширину строки считать контейнером с внутренними отступами, а не обещанным количеством символов.
5. Перенести подходящие компоненты: кнопки, поля, навигацию, подсказки, меню и диалоги. Образцы в [design.json](../apps/desktop/.impeccable/design.json) содержат самодостаточный HTML/CSS для визуального просмотра; поведение берётся из описания и исходных компонентов.
6. Реализовать локальные оконные действия и размещение панелей. Сохранить фокус, выделение, IME, прокрутку и черновики при открытии/закрытии инструментов и переключении темы.
7. Проверить фактический UI принимающего приложения по матрице ниже и записать отличия в его собственный `DESIGN.md`. Имена и тексты интерфейса остаются продуктово-специфичными.

## Матрица приёмки переноса

Это критерии будущего переноса, а не заявление, что все проверки выполнены здесь.

| Сценарий | Что сравнить |
|---|---|
| Светлая/тёмная базовые темы | Поверхности, текст, focus, меню, диалоги, подсказки и редактор |
| Явная тёмная тема при светлой ОС | Вложенный редактор и маркеры сохраняют выбранную тему |
| Системная тема, смена схемы ОС | Все части окна меняются согласованно без перезапуска |
| Другая тема каталога | Используются семантические роли, а не захардкоженная базовая палитра |
| Независимое изменение UI/книжного шрифта | Подсказки и формы остаются UI-текстом; документ — книжным |
| Широкое/минимальное окно, длинные русские названия | Нет потери действий и необратимого обрезания содержимого; панели доступны |
| Клавиатура | Focus-visible, Tab, Escape, возврат фокуса, ресайз панелей |
| Выделение и ввод | Popover не ломает выделение; поиск не создаёт сигнал; оформление не сбрасывает IME |
| Ошибки/disabled/недоступные записи | Состояние понятно по тексту, а не только цвету |
| Модальный/немодальный слой | Правильная модальность, clipping, позиция, доступность закрытия |

GUI-проверки на Linux выполняются исключительно в отдельном Xvfb с `ELECTRON_OZONE_PLATFORM_HINT=x11`. Проверка macOS — отдельный платформенный этап. Здесь сестринские репозитории не изменялись.

## Особенности, которые не следует тиражировать

См. раздел «Зафиксированные исключения» в [DESIGN.md](../apps/desktop/DESIGN.md). Отсутствующий `--app-muted` и конфликт слоёв metadata/sidebar не становятся нормами. Новые цветовые ramps, эстетические метафоры и декоративные состояния не добавлялись: задача — зафиксировать существующий интерфейс.
