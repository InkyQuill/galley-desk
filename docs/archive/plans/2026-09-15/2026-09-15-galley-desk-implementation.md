**Goal:** Реализовать согласованную первую версию Galley Desk и необходимые изменения трёх связанных проектов.

**Architecture:** Работа разделена на четыре самостоятельных плана. Android-совместимость и общие библиотеки дают самостоятельные проверяемые результаты; чистые пакеты Desk проходят межъязыковые тесты до подключения desktop-интерфейса.

**Tech Stack:** Electron, React, TypeScript, CodeMirror/Galley, Kotlin/Compose, npm/Bun, Vitest/JUnit/Playwright

## Global Constraints

- Основные платформы: Linux и macOS.
- Обычный ввод создаёт правки в sidecar; исходный Markdown не меняется.
- Схемы v1 не расширяются дополнительными полями Galley Desk.
- Пересечение сохранённых диапазонов не является причиной отвергать весь sidecar при чтении или записи.
- Сигналы могут пересекаться.
- Закрытие книги/проекта очищает оба стека всех глав.
- Renderer работает с включённой изоляцией контекста, без Node integration.
- В рамках реализации разрешены необходимые изменения Galley Editor, Galley Pad и Pocket Editor; существующее поведение этих проектов не является неизменяемым ограничением.
- Правка / сигнал — термины интерфейса; не «предложение». Исходный Markdown сохраняет точные UTF-8 bytes и переводы строк.
- На время выполнения проверить AGENTS.md соответствующего репозитория и рабочее дерево. Существующие изменения других агентов/пользователя не отменять. Изолированный worktree создавать только при выполнении плана.
- Тестовые фрагменты ниже — начальные исполняемые регрессии, алгоритмы — конкретные опорные участки; остальные перечисленные примеры добавлять отдельными короткими циклами RED/GREEN. Не считать один пример полной проверкой задачи.

## Планы и порядок выполнения

| План | Задачи | Результат |
| --- | --- | --- |
| [Pocket Editor](2026-09-15-pocket-editor-compatibility.md) | P1–P4 | Android читает/сохраняет недоступные и конфликтующие записи, показывает их без перепривязки |
| [Общие библиотеки](2026-09-15-galley-shared-libraries.md) | L1–L3 | Общий пакет тем, работающий Galley Pad, проверенный контракт транзакций Galley |
| [Логика Galley Desk](2026-09-15-galley-desk-core.md) | C1–C6 | Формат, производный текст, сигналы, локальная запись и восстановление |
| [Desktop](2026-09-15-galley-desk-desktop.md) | D1–D5 | Рабочее приложение, рецензирование и проверенные сборки |

Практический линейный порядок:

1. C1 — минимальная сборка чистого пакета и codec.
2. D1 — сразу проверить запуск и упаковку Electron на основной машине.
3. P1 → P2 → P3 → P4 — совместимость Android и Kotlin fixtures.
4. C2 — двусторонний контракт на реальных Kotlin/TypeScript реализациях.
5. L1 → L2 → L3 — общие темы, Pad и публичный API.
6. C3 → C4 → C5 → C6 — умное редактирование, сигналы, сохранение и применение.
7. D2 → D3 → D4 → D5 — интерфейс и полная проверка.

При выбранном пользователем режиме субагентов независимы P1–P4 и L1–L3, но два исполнителя не должны одновременно менять один репозиторий. Сначала согласовать владение файлами. Этот план сам не запускает агентов и не изменяет код приложений.

## Правила выполнения

- Перед каждой задачей читать её Interfaces и предыдущие результаты, не переименовывать API соседней задачи без обновления всех consumers.
- Каждый пункт Step — отдельное действие; дополнительные сценарии в конце задачи выполнять отдельными RED/GREEN циклами. Если шаг растёт, дробить по перечисленным случаям, не откладывать проверку до конца подсистемы.
- План содержит опорные тесты и алгоритмы, а не готовый патч всего приложения. Ошибка установки зависимостей не доказывает RED. Характеристические тесты существующего Galley могут сразу быть GREEN: тогда не ломать реализацию искусственно.
- У каждого Task есть Files, Consumes/Produces, тест, конкретный алгоритм, команды проверки и conventional commit. Коммиты создаются при выполнении, не на этапе записи планов.
- Новый проект сейчас не Git repository; инициализация входит в C1. Existing documentation и tool artifacts не удалять; `.remember`/`.pi` не включать автоматически в первый commit.
- Не тянуть применение desktop-правок в Android. Pocket Editor в этом плане только терпимо читает/сохраняет рецензии и показывает доступность.
- Не делать SQL-хранилище, сервер, поиск всех книг, постоянный Undo, переносимый журнал или realtime collaboration.
- В первой версии пустой исходный файл остаётся read-only для создания правки; расширение wire format не требуется для выбранного объёма.
- Обновление пакетов и выпуск Pocket Editor — зависимость финальной совместимости. До реального выпуска указывать tested commit, не придумывать номер минимальной версии.

## Финальный gate

- [ ] Pocket Editor: `./gradlew test lint assembleDebug compileDebugAndroidTestKotlin`, выполненные instrumentation tests.
- [ ] Galley Editor: unit, lint, library build, docs/Storybook build, consumer tarballs.
- [ ] Galley Pad: `mise run verify`, реальная интеграция без mock редактора.
- [ ] Galley Desk: typecheck, unit/storage tests, Kotlin exchange, package, Electron workflows.
- [ ] Проверенные packaged-сборки Linux и macOS, список машин и результатов в docs/verification.md.
- [ ] Передача папки между приложениями сохраняет active/stale/conflicting records и chapter_note; применение удаляет только выбранную правку.

Невыполненный platform gate не скрывать под «все тесты прошли». Отсутствующие credentials выпуска не подменять заявлением о публикации; подготовленная сборка и опубликованный релиз — разные результаты.

## Самопроверка плана

Покрытие спецификации сведено в таблицу выше. Имена wire types не переводятся; Range в pocket-format — bytes, TextChange/RecordView — UTF-16. ChapterSession владеет обеими историями; Snapshot только сериализуемый UI DTO. Из планов убраны предположения о бессрочном Undo, обязательном новом API позиций Galley и атомарной замене двух файлов.
