# Galley Desk

Приложение для Linux и macOS для рецензирования Markdown-книг. Пользователь открывает папку книги и редактирует текст; изменения сохраняются как правки в формате Pocket Editor. Отдельную правку можно вручную применить к Markdown или отклонить.

Стек: Electron, React, TypeScript, Galley Editor и Galley Themes. Реализован основной настольный контур: открытие папок и недавних книг, редактирование с session Undo, сигналы и заметки главы, виды «Текст»/«Сравнение»/«Исходник», поиск по главе, фильтр оглавления, оформление (темы Galley, шрифт, ширина строки), режим Zen, упаковка Electron Forge и Electron-тесты по собранному JS. После [аудита реализации](docs/reviews/2026-09-16-implementation-audit.md) выполнены исправления сохранности данных и [проверка Linux/совместимости](docs/reviews/2026-09-16-local-integration.md). Реальная macOS пока не проверена. Текущие исправления по работе с книгами описаны в [отчёте](docs/reviews/2026-09-16-real-book-fixes.md).

## Установка

Готовые пакеты для Linux и macOS: [GitHub Releases](https://github.com/InkyQuill/galley-desk/releases/latest).
Для Linux после первого опубликованного релиза:

```sh
(installer=$(mktemp) && trap 'rm -f -- "$installer"' EXIT && curl -fsSL https://github.com/InkyQuill/galley-desk/releases/latest/download/install.sh -o "$installer" && bash "$installer")
```

[Полная инструкция](docs/installation.md): системные deb/rpm/pacman, требования,
проверка checksum, обновление, откат и удаление. macOS-сборки пока не подписаны
и не нотарифицированы; инструкция описывает первый запуск.

## Разработка и сборка

Нужен Node >=22.13 (CI использует Node 24) и npm. Из корня репозитория:

- `npm ci` — зависимости и бинарник Electron.
- `npm run typecheck` и `npm test` — типы и unit-тесты.
- `npm audit` — аудит всех зависимостей, включая инструменты сборки.
- `npm run check:release` — проверка версий и релизной обвязки.
- `npm run test:contracts` — обмен с закреплённой редакцией Pocket Editor (JDK 17).
- `npm run package` — приложение в `apps/desktop/out/`.
- `npm run make` — Linux ZIP/deb/rpm или macOS ZIP.

Запуски GUI при разработке и автоматизированных проверках изолируются:

```sh
scripts/gui-test.sh npm start
npm run package
GALLEY_PACKAGED_EXECUTABLE="$PWD/apps/desktop/out/galley-desk-linux-x64/galley-desk" \
  scripts/gui-test.sh npm run test:desktop -- --workers=1
```

Релизами управляет release-please: слияние `chore: release X.Y.Z` запускает
проверку и публикацию бинарников. [Первое включение и повтор выпуска](docs/runbooks/release.md).

## Диагностика

Приложение ведёт локальный журнал диагностики (не рукописи) для расследования аварий и сбоев: старт/остановку сессии, необработанные исключения основного и renderer-процессов, аварийное завершение renderer/дочерних процессов, отказы IPC-обработчиков и внутренние сбои сервиса книги. Журнал открывается из панели «Диагностика» (кнопка со значком ⓘ в заголовке окна — доступна и с экрана недавних книг, и при открытой книге; на macOS дублируется пунктом «Справка → Диагностика» приложения, `Cmd+Shift+D`).

- **Путь журнала**: `<профиль приложения>/logs/diagnostics.log` — то есть относительно `app.getPath('userData')` (на Linux обычно `~/.config/Galley Desk/logs/diagnostics.log`, на macOS — `~/Library/Application Support/Galley Desk/logs/diagnostics.log`). Кнопка «Открыть папку журнала» в панели открывает именно эту папку через `shell.openPath`, создавая её заранее, если она ещё не существует; если создать папку или открыть её не удалось, панель показывает явную ошибку, а не молчит.
- **Ротация**: активный файл `diagnostics.log` ограничен 2 МиБ; при превышении лимита он переименовывается в `diagnostics.log.1` (предыдущий `.1` становится `.2`, а прежний `.2` удаляется), после чего пишется новый пустой активный файл. Хранятся не более трёх файлов (активный + два резервных) на профиль.
- **Формат**: JSON Lines — одна запись на строку, каждая содержит `event`, `level`, `process`, `timestamp`, `sessionId`, версию приложения/сборки/Electron/редактора/тем и (для части событий) безопасный `code` и до 20 очищенных кадров стека вида `файл:строка:столбец` — никогда полный путь, сообщение исключения или содержимое книги.
- **Как приложить журнал к сообщению об ошибке**: откройте панель «Диагностика», нажмите «Открыть папку журнала» и вручную приложите файл(ы) `diagnostics.log`/`diagnostics.log.1`/`diagnostics.log.2` к письму или тикету. Кнопка «Скопировать сведения» копирует в буфер обмена только версию приложения, сборку, платформу/архитектуру, версии Electron/редактора/тем и статус журнала («Ведётся»/«Недоступен») — сам файл журнала она не прикладывает и никуда не отправляет.
- **Ограничения аварийного логирования**: запись в момент необработанного исключения основного процесса (`process.on('uncaughtExceptionMonitor', …)`) не отменяет и не откладывает штатное аварийное завершение Node — это только наблюдатель, а не перехватчик. Запись при выходе (`session-end` и сброс буфера журнала) ограничена по времени (не более ~500 мс), чтобы не задерживать закрытие приложения; после аварийного завершения renderer-процесса приложение не обещает сохранить незафиксированные изменения книги — это гарантирует только штатное закрытие. Если файловая система журнала недоступна (нет прав, диск переполнен и т.п.), логирование за сессию отключается («Недоступен» в панели), но само приложение продолжает работать в обычном режиме.
- **Известное ограничение macOS**: сбой аварийного завершения по сигналу выбора текста (selection-signal crash) на macOS, отложенный пользователем и описанный в [спецификации диагностики и рабочего пространства](docs/superpowers/specs/2026-09-17-diagnostics-and-workspace-ux.md), этой задачей не устранён и не считается исправленным — диагностика лишь фиксирует такие аварии в журнале (`renderer-gone`/`uncaught-main`), если они происходят, но не предотвращает их и не смягчает их причину.
- **Что никогда не попадает в журнал и в диагностическую сводку**: текст книги, комментарии рецензии, YAML-метаданные, произвольные пути файловой системы и содержимое сообщений исключений. Автоматической отправки диагностики куда-либо (по сети, в облако и т.п.) нет — журнал полностью локален, а перенос данных возможен только вручную через файловую систему.

## Связанные проекты

Реализация включает необходимые изменения Pocket Editor, Galley Editor и Galley Pad в их отдельных репозиториях; проверенные редакции перечислены в [docs/compatibility.md](docs/compatibility.md). Совместимость с недоступными и конфликтующими правками требует обновлённого Pocket Editor; существующие старые версии могут отвергать такие файлы.

## Безопасность

`npm audit` проверяет зависимости, включая сборочные инструменты. Unit- и Electron-тесты
проверяют IPC, sandbox, навигацию и доступ к ресурсам. Устаревший Electronegativity
удалён; эти проверки не выдаются за универсальный статический анализ.
[Модель безопасности и ограничения](security.md).
